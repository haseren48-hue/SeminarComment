# サーバー設置手順

参加者が4G / 5Gからも接続するには、インターネットから到達できるHTTPSサーバーが必要です。
手元のDocker構成は、既存のサーバー1台で運用するためのものです。
アカウント作成や有料契約、外部への公開は実行していません。

## DockerとCaddyで起動する

1. Docker Composeを使えるサーバーへソースを配置し、所有するドメインのDNSをそのサーバーへ向けます。80番と443番のTCPポートをCaddyに割り当てます。
2. `deploy/.env.example`を`deploy/.env`へコピーし、`DOMAIN`に実際のホスト名を設定します。`PRESENTER_KEY`には次のコマンドで生成した値を設定します。

   ```sh
   node -e "console.log(require('node:crypto').randomBytes(32).toString('base64url'))"
   ```

3. `deploy/`で次を実行します。

   ```sh
   docker compose up -d --build
   ```

4. `https://設定したホスト名/healthz`を開き、`{"ok":true}`を確認します。発表者アプリの接続設定へ同じHTTPS URLと作成キーを入力します。
5. セッションを作成し、スマートフォンのモバイル回線からQRを読み取って試験投稿します。サーバー再起動と通信断の挙動も会場利用前に確認します。

Caddyは証明書とその管理情報をDockerボリュームへ保存します。
コメント本文は保存しません。
この構成ではCaddyのアクセスログを有効にしていません。
Dockerイメージのビルド、証明書取得、外部回線からの接続は、この開発環境では未検証です。

## Node.jsを直接起動する

Node.js 24以降がある環境では、プロキシの内側でサーバーを直接起動できます。
依存パッケージをインストールした後、次の環境変数を設定します。

| 変数 | 内容 |
|---|---|
| `PRESENTER_KEY` | セッション作成キー。16文字以上 |
| `PUBLIC_URL` | 参加URLの基点。例 `https://comments.example.org` |
| `HOST` | 既定値 `127.0.0.1`。コンテナー内では `0.0.0.0` |
| `PORT` | 既定値 `8787` |

```sh
node server/index.mjs
```

公開時はTLSを終端するプロキシでWebSocketのUpgradeを中継します。
サーバーとWeb画面は同じホスト名で提供します。
複数プロセスや複数レプリカには分散させず、1プロセスで運用します。
セッション情報をメモリーに保持するため、別プロセスへの接続は同じセッションを認識しません。

## キー交換と停止

作成キーを交換する場合は、`PRESENTER_KEY`を更新してサーバーを再起動し、アプリの「接続設定」も更新します。
アプリはキーを端末のユーザーデータフォルダー内の`connection.json`へ保存します。
設定ウィンドウにキーの現在値は表示しません。
アプリと同じ実行ファイルのフォルダーに`seminar-config.json`を置く構成にも対応しますが、Macではアプリバンドル内部に置く必要があるため、通常は設定画面を使用します。

```json
{
  "serverUrl": "https://comments.example.org",
  "presenterKey": "運用者が生成したキー"
}
```

サーバーを停止すると参加中のブラウザーへ終了通知を送り、全セッションを破棄します。
プロセスの異常終了や停電では通知が届かない場合がありますが、次の通信や再接続で終了を検知します。
コメント本文を含むHTTPリクエスト本文、WebSocketメッセージ、メモリーダンプを監視基盤へ転送しない運用にしてください。

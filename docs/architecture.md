# 構成と技術選定

0.2.0では、デスクトップアプリがNode.jsの通信サーバーを内蔵して起動します。
「スマホから参加」では同梱したcloudflaredによる試験用のHTTPS接続を追加します。
通常運用向けの独立したサーバーへ接続する方式も維持します。


発表者アプリはElectron、参加者画面はHTML / CSS / JavaScript、サーバーはNode.jsと`ws`を使います。
Electronは配布容量が大きくなる一方、透明ウィンドウ、最前面表示、クリック透過、画面選択を同じAPIで組み合わせやすいため採用しました。
Tauriは配布容量を抑えやすい候補ですが、今回最優先のウィンドウ動作の検証を先に進めるため、Electronで初期実装を作りました。
Tauriとネイティブ実装について同条件での実機比較は行っていません。

## アプリのウィンドウ

設定ウィンドウと透明オーバーレイを分けています。
通常時はオーバーレイをフォーカス不可にし、`setIgnoreMouseEvents(true)`でマウス操作を下のウィンドウへ通す設定にします。
領域編集中だけフォーカスとマウス操作を有効化します。
編集完了とEscの両方で元へ戻します。

macOSではウィンドウの種類を`panel`に設定して全画面アプリ上への表示を補助します。
`setVisibleOnAllWorkspaces(true, {visibleOnFullScreen:true})`を設定し、最前面レベルを`screen-saver`とします。
ウィンドウの座標はElectronのディスプレイ情報に合わせ、倍率差を含めてDIP単位で扱います。
`enableLargerThanScreen`によりmacOSメニューバー分の下方向への補正を防ぎます。
この環境では実ウィンドウの座標とディスプレイの座標が一致することを確認しました。
PowerPointやOSの全画面描画方式による差は、会場の実機で確認する必要があります。

画面が抜かれた場合はプライマリーディスプレイへ移動します。
領域は画面に対する比率で保存するため、解像度が変わっても同じ割合を使います。
ディスプレイIDはOSの再検出で変わる場合があり、その場合は選択し直します。

[ElectronのBrowserWindow API](https://www.electronjs.org/docs/latest/api/browser-window)に、最前面表示、全画面上での表示、クリック透過の仕様が記載されています。
これらは実装の根拠であり、PowerPoint上での成功を保証するものではありません。

## リアルタイム通信

参加者はRoom Codeまたは32文字のランダムIDでセッションを解決し、HTTP POSTでコメントを送信します。
サーバーは発表者として認証済みのWebSocket接続へだけコメント本文を配信します。
参加者のWebSocketでは接続状態と終了通知だけを受信します。
参加者へ他人のコメント一覧を配信するAPIはありません。

作成キーはHTTPヘッダー、セッションごとの終了／受信用トークンはHTTPヘッダーまたはWebSocketの初回メッセージで送ります。
トークンをURLへ入れません。
発表者用のキーを参加者のHTMLへ埋め込みません。
セッション作成はキー照合に加え、サーバー全体で1分間に12回までに制限します。
参加者単位の投稿間隔制限はありません。

発表者接続には自動再接続を実装し、切断中のコメント履歴は再送しません。
サーバーは切断検知のため15秒ごとにpingを送り、応答のない接続を次回に閉じます。
ネットワーク経路によって、瞬断を検知するまで約30秒以上かかる場合があります。

## 本文の扱い

ブラウザーとサーバーの両方で`Intl.Segmenter`のgrapheme単位により30文字までに制限します。
入力中はIME変換を妨げないよう制限を保留し、変換確定時に30文字へ収めます。
合成途中の文字列は一時的に30文字を超える場合があります。
単一graphemeに結合文字を大量に付ける送信への対策として、本文に2048バイト、HTTP／WebSocketメッセージに4096バイトの上限を設けています。
通常の絵文字は利用できます。

DOMへは`textContent`で描画します。
URLもHTMLもそのままの文字列として扱います。
レンダラーはNode.js無効、context isolation有効、sandbox有効とし、外部ナビゲーションと追加ウィンドウの生成を拒否します。
IPCは送信元ウィンドウと操作の組み合わせを確認します。
[Electronのセキュリティ指針](https://www.electronjs.org/docs/latest/tutorial/security/)に沿った設定です。

## 配布

MacはApple SiliconとIntel用のZIP、Windowsはx64用の展開起動用ZIPを用意します。
単一のportable EXEを作る設定も用意していますが、Mac上のNSIS処理で失敗したため、この環境での成果物はZIPです。
Windowsのポータブル形式については[electron-builderの配布形式](https://www.electron.build/v26/docs/targets/)を参照しています。
単一EXEの形式をWindows上でビルドして使う場合には、起動時の展開用にユーザーの一時フォルダーへの書き込みが必要です。
インストーラーによる管理者権限の要求はありませんが、端末の実行制限には従います。
正式配布時の署名、公証、SmartScreenでの評価確認は今後の作業です。
